# 引き継ぎ（handoff）

他方のAIが、人間からの状況説明なしに作業を再開できる状態を作ってから終了する。

## 実行順序（厳守）

順序を入れ替えないこと。`HANDOFF.md` の更新を push より後に行うと、その更新は commit に含まれず相手に届かない。

### 1. HANDOFF.md を上書き更新する

リポジトリ直下の `HANDOFF.md` を、以下の形式で**上書き**する（追記しない）。20行以内に収める。

```markdown
# HANDOFF

- 更新: YYYY-MM-DD HH:MM JST
- 更新者: Claude Code
- 対象Issue: #12
- 作業ブランチ: claude/xxx
- PR: #13
- 状態: 作業中 | レビュー待ち | 完了

## いま何をしていたか
（1〜3行）

## 次にやること
（箇条書き。最大3つ）

## 詰まっている点・人間の判断が必要な点
（なければ「なし」）
```

Issue・ブランチ・PR番号の3つは必須。再開側はこれを頼りに現場へ到達する。
未作成のものは「なし」と明記し、空欄にしない。

### 2. Issue へ進捗コメント（中断する場合）

対象 Issue に、担当AI・作業ブランチ・現在の状態・次の一手を1コメントで残す。
新しいセッションは `main` を開くため、**Issue だけが確実に読まれる入口**である。

### 3. commit

`HANDOFF.md` の変更を必ず含める。

### 4. push

`git push -u origin <branch-name>`。

### 5. PR を作成 / 更新

レビュー可能な状態なら PR を作成、既にあれば説明文を更新する。
設計判断とその理由は PR 説明文に書く（`HANDOFF.md` には履歴を残さない）。

## チェック

終了前に確認する。

- [ ] `HANDOFF.md` に Issue・ブランチ・PR が書かれているか
- [ ] `HANDOFF.md` が commit に含まれているか
- [ ] push 済みか（`git status` がクリーンか）
- [ ] 作業が未完了でも上記を実行したか

未完了を理由に push を省略しない。相手から見れば、push されていない作業は存在しない。
